## 1. 项目定位与非目标

### 定位

跨平台拟真赛车模拟器。核心差异化：

- **物理拟真度为第一优先级**，不做"平台化手感"
- **直接兼容 Assetto Corsa 模组生态**：车辆、赛道、皮肤、音频、驾驶员、天气、后处理
- **加载时直读 AC 原格式**，不做资产转换、不重新打包
- 客户端与服务端解耦，服务端可联邦部署（见 Server 项目方案）

### 非目标

- 不做街机化辅助（辅助驾驶为可选开关，不影响物理核心）
- 不做资产再分发（只读用户本地已有的模组）
- 不做确定性 lockstep 物理（联机用服务器权威 + 客户端预测）
- 第一版不追求 100% CSP 特性覆盖（明确降级 + 日志，不静默失败）
- 不做 ACTools 那样的通用格式转换器（只覆盖本项目需要的子集）

## 2. 技术栈与总体架构

```
┌────────────────────────────────────────────────┐
│  Godot 4                                        │
│  渲染 / UI / 输入 / 音频输出 / 场景管理            │
│    ↑  GDExtension（薄适配层，同进程）             │
│  ┌────────────────────────────────────────────┐ │
│  │  Rust 物理核心（纯 crate，无引擎依赖）         │ │
│  │   sim-core / sim-tire / sim-susp            │ │
│  │   sim-drivetrain / sim-aero / sim-vehicle   │ │
│  │   固定步长 360 Hz                            │ │
│  └────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────┐ │
│  │  Rust 资产层（AC 格式直读，无引擎依赖）         │ │
│  │   通用：kn5 / ini / acd / tex / ai / ksanim │ │
│  │        bank / guids / json                  │ │
│  │   组合：car / track / showroom               │ │
│  │        driver / weather / postprocess        │ │
│  └────────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────────┐ │
│  │  适配转换层（唯一知道 Godot 存在的地方）        │ │
│  │   Rust 结构 → ArrayMesh / Material / Image   │ │
│  │              / AudioStream / Animation       │ │
│  └────────────────────────────────────────────┘ │
└────────────────────────────────────────────────┘
```

### 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 引擎 | Godot 4 | 开源、跨平台、GDExtension 成熟、零基础友好 |
| 语言边界 | Rust 做物理与资产解析，GDScript 做 UI/流程 | 物理性能与数值可控；UI 迭代快 |
| 进程模型 | 同进程 GDExtension | 避免 IPC 延迟与序列化开销 |
| 物理步长 | 360 Hz 固定步长 | 轮胎刚性需要高频；与渲染帧解耦 |
| 渲染插值 | 物理状态双缓冲插值 | 360 Hz → 任意帧率平滑 |
| 资产策略 | 加载时直读原格式 | 无转换步骤、无打包、模组改了即生效 |
| 联机 | 服务器权威 + 客户端预测 | 不做 lockstep（跨平台确定性成本极高） |

## 3. 核心设计原则（三条铁律）

这三条是整个架构的地基，违反任何一条都会在后面对冲掉大量返工。

### 铁律一：物理核心不依赖引擎

所有 `sim-*` crate 不 `use godot::*`。可独立 `cargo test`，可跑无头基准，可未来搬走。
Godot 只通过适配层与物理对话，一次调用、一个数组进出。

### 铁律二：资产直读，零转换，零打包

不产出 `.glb` / `.gltf` / `.tscn` / `.tres`，不生成中间资产目录，没有"先转换再运行"。
kn5 在加载时解析成内存顶点/索引/材质，直接构造 Godot 资源；ini/acd 直接解析成 Rust struct；
dds 解码成 RGBA 直接喂 Godot Image；bank 解码成 PCM 直接喂 AudioStream。
用户装模组 = 丢进目录，改了就生效。

### 铁律三：宁可明确报错，不静默降级

不支持的 shader、加密的 kn5、缺失的必填参数、格式变体——**全部明确报错并给出具体位置**。
静默降级到"看起来能跑但手感错"会直接毁掉"拟真"这个唯一卖点。

## 4. 物理核心

### 4.1 crate 划分

| crate | 职责 | 依赖 |
|---|---|---|
| `sim-core` | 定步长积分器、状态容器、时间管理、单位约定 | 无 |
| `sim-tire` | MF6.1 + 热/压/载荷耦合 | sim-core |
| `sim-susp` | 悬挂几何、弹簧/阻尼/防倾杆、行程限制 | sim-core |
| `sim-drivetrain` | 扭矩曲线、离合、变速箱、差速器 | sim-core |
| `sim-aero` | 阻力、下压力、地面效应、尾流 | sim-core |
| `sim-vehicle` | 刚体装配、四轮受力合成、ABS/TC | 以上全部 |
| `ac-params` | AC 参数 → 物理核心映射（纯数据） | 无 |

### 4.2 约束

- 所有 `sim-*` 不依赖 Godot，可独立 `cargo test`
- 物理核心不读文件，输入由上层构造好结构体传入
- 热路径不分配堆内存，用固定大小数组与栈上结构
- 单位内部统一 SI，边界处转换，核心内不转换

### 4.3 数值方法

- 积分器：半隐式欧拉（symplectic Euler），360 Hz
- 每步顺序：
  1. 采样输入（转向、油门、刹车、挡位）
  2. 计算四轮滑移率 / 侧偏角
  3. 轮胎力（MF6.1，含组合滑移）
  4. 悬挂力（弹簧、阻尼两段、防倾杆、bump stop）
  5. 气动力（含地面效应、尾流）
  6. 传动系扭矩分配
  7. 刚体合成 → 线速度/角速度积分
  8. 碰撞检测与响应（赛道物理网格）
- 渲染帧从两个物理状态插值

### 4.4 单位约定

| 量 | 内部 | UI 显示 |
|---|---|---|
| 长度 | m | km/h、m |
| 质量 | kg | kg |
| 力 / 力矩 | N / N·m | N / N·m |
| 角度 | rad | deg |
| 转速 | rad/s | rpm |
| 功率 | W | kW / hp |
| 压力 | Pa | psi / bar |
| 温度 | K | °C |

**边界转换，核心内不转换。**

## 5. 轮胎模型

### 5.1 选型

Pacejka Magic Formula 6.1：

- 纵向力 Fx(κ, Fz, γ, p)
- 侧向力 Fy(α, Fz, γ, p)
- 回正力矩 Mz
- 组合滑移（similarity method）
- 胎温（表层/内层/胎体三层）、胎压对峰值与刚度的修正
- 载荷敏感性与载荷转移

### 5.2 参数来源与映射

AC `tyres.ini` 提供：

- `[FRONT]` / `[REAR]` 段
- `RADIUS`、`WIDTH`、`RIM_RADIUS`
- `PRESSURES`（冷/热）、`VERTICAL`、`RELAXATION`
- `DY0`、`DX0`、`B0`、`C0`、`E0` 等 MF 系数

映射策略：

1. ini 给出 MF 系数 → 直接映射
2. 只给简化参数（`FY_MAX`、`SLIP_ANGLE_PEAK`）→ 反解器从峰值点与曲率反推 MF 系数
3. 缺失项用同类车模板（按重量/驱动/轮胎类型）补全，标记 `Inferred`

**所有推测值进遥测标记**，便于后续校准。

### 5.3 第一天就要做的验证

唯一硬标准：**与 AC 原版同车同赛道同输入的遥测对比**。

1. AC 里录一段遥测
2. 本引擎用相同初始条件与输入序列跑
3. 对比车速、滑移角、轮胎载荷、横向加速度、圈速

容差：圈速 < 2%，峰值横向加速度 < 5%，稳态转向趋势一致。

**这条不通过，其他都不用做。**

## 6. 悬挂、传动、气动

### 6.1 悬挂

- 双叉臂几何（`suspensions.ini` 硬点）
- 弹簧、阻尼（低速/高速两段）、防倾杆、bump stop
- 转向几何：阿克曼、主销后倾/内倾、scrub radius
- 输出：接地点位置、载荷、外倾角随行程变化

### 6.2 传动

- 发动机：`[TORQUE_CURVE]` 或功率曲线
- 离合：接合曲线、滑摩
- 变速箱：齿比、换挡时间、自动离合
- 差速器：开放式、锁止率、预载、扭矩矢量
- 驱动形式：FWD / RWD / AWD

### 6.3 气动

- 阻力 Cd × A
- 前后轴下压力 Cl × A ∝ v²
- 地面效应：随车高查表
- 尾流：距离衰减模型
- 冷却：刹车温度、水温（影响性能，V2）


参数来源优先级：

2. `engine.ini` / `drivetrain.ini`
3. `suspensions.ini`
4. `tyres.ini`
5. `aero.ini`
6. `brakes.ini` / `electronics.ini` / `fuel.ini`
7. `acd`（补充与交叉校验，**ini 优先**）

**优先读 ini**：文本可读、模组作者常改；acd 是编译产物。
ini 与 acd 冲突时以 ini 为准并记警告。

## 8. GDExtension 适配层

### 8.1 原则

- **薄**：只做数据搬运，不含物理逻辑
- **每帧一次进出**：传输入数组 → 跑 N 个物理步 → 返回状态数组
- **不做逐对象跨边界调用**（性能杀手）
- 资产转换也只在这一层做（Rust 结构 → Godot 资源）

### 8.2 接口草案

```rust
#[godot_api]
impl RacingSim {
    #[func]
    fn step_frame(&mut self, inputs: PackedFloat32Array, dt: f64) -> PackedFloat32Array;
}
```

返回：车辆位姿、四轮状态（转速/滑移/侧偏/载荷/温度/接地点）、发动机状态、HUD 派生量。

### 8.3 时间管理

```
渲染帧 dt（可变）
  → accumulator += dt
  → while accumulator >= 1/360: 物理步
  → 剩余比例用于插值
```

**禁止**物理步长随帧率变化。

## 11. 通用格式解析基础

### 11.1 kn5 解析器（`ac-kn5`）

**结构**：

```
Header
  magic: "sc6969"（或版本变体）
  version: u32
Node 树（递归）
  node_type: u32      // 0=dummy, 1=mesh, ...
  name: string
  transform: 4x4 f32
  [mesh] vertex_count, index_count
         positions/normals/uvs/tangents?/colors?
         indices, material_id
Material 表
  name, shader_name, 参数 KV, 纹理槽位
Texture 表
  文件名引用
```

**实现要点**：

1. **流式解析**：`BufReader` 顺序读，边读边构造，不一次读全文件
2. **节点树**：保留层级（挂点、轮子、可动部件）
3. **变换矩阵**：行/列主序需实测确认，不凭猜
4. **法线缺失**：按索引重建（面积加权）
5. **切线**：kn5 通常不存，按 UV 计算（Godot normal map 需要）
6. **LOD**：按命名约定或节点属性识别
7. **加密变体**：检测后明确报错，不静默失败

**输出**：

```rust
pub struct Kn5Scene {
    pub nodes: Vec<Kn5Node>,        // 扁平化 + parent 索引
    pub meshes: Vec<MeshData>,
    pub materials: Vec<MaterialDef>,
    pub textures: Vec<TextureRef>,
    pub animatable_nodes: Vec<NodeRef>,  // 带动画的节点
}

pub struct MeshData {
    pub positions: Vec<[f32; 3]>,
    pub normals: Vec<[f32; 3]>,
    pub uvs: Vec<[f32; 2]>,
    pub tangents: Vec<[f32; 4]>,    // 计算得出
    pub indices: Vec<u32>,
    pub material_id: usize,
    pub cast_shadows: bool,
}
```

**到 Godot 的转换（适配层，内存中）**：

```rust
let mut arrays = VariantArray::new();
arrays.push(&positions.to_packed_vector3_array());
arrays.push(&normals.to_packed_vector3_array());
arrays.push(&tangents.to_packed_float32_array());
arrays.push(&uvs.to_packed_vector2_array());
arrays.push(&Variant::nil());            // 顶点色
arrays.push(&indices.to_packed_int32_array());

let mut mesh = ArrayMesh::new_gd();
mesh.surface_set_name(0, &name);
mesh.add_surface_from_arrays(Mesh::PRIMITIVE_TRIANGLES, &arrays);
```

### 11.2 ini 解析器（`ac-ini`）

**容忍度要求**：

- 注释：`;` 和 `//`
- 重复键：后者覆盖（记警告）
- 键名大小写不敏感
- 缺失段：返回 `MissingSection` 错误，不静默空
- 单位后缀：`"1.2 m"`、`"300 N/mm"`、`"45 deg"` 需解析
- 数值格式：`.5` / `5.` / 科学计数法 / 千分位逗号

**输出**：强类型 struct，不用 `HashMap<String, String>` 透传。每个字段有归属的 struct，缺必填项编译期可见。

### 11.3 acd 解析器（`ac-acd`）

- acd 是编译后二进制，含 ini 没有的运行时数据
- **只用 ini 能读的就不解 acd**；acd 用于补齐与交叉校验
- 格式逆向仍需自行实现（参考规范，不调用外部工具）
- 版本差异大，需按版本号分派解析路径
- 解析失败的字段降级为 `Inferred` 并记日志

### 11.4 纹理解析（`ac-tex`）

**格式**：

- `.dds`：DXT1 / DXT3 / DXT5 / RGBA8 / BGRA8 / R8（部分为法线或遮罩）
- `.png` / `.jpg`：标准图片
- `.ktx`：少数 CSP 模组（P3）

**DDS 流程**：

```
读 header → 识别 fourCC / DXGI 格式
         → 解码为 RGBA8（DXT 解码自实现或用 squish crate）
         → Image::create_from_data
         → generate_mipmaps
         → ImageTexture
```

**要点**：

- **不依赖 Godot 的 dds 导入管线**（那是编辑器导入期行为，运行时不可控）
- 大纹理（4K）后台线程解码，先用 1×1 占位色
- **色彩空间**：颜色贴图走 sRGB，法线/粗糙度/Metalness/AO 走线性，**不能混**
- 纹理数组 / 图集：部分模组用，需按 shader 参数拆通道

### 11.5 材质映射

AC shader → Godot 材质：

| AC shader | Godot | 说明 |
|---|---|---|
| `ksPerPixel` | `StandardMaterial3D` | 基础 |
| `ksPerPixelNM` | `+ normal_texture` | 法线 |
| `ksPerPixelNM_TxAO` | `+ ao_texture` | AO 在 alpha 或独立贴图 |
| `ksPerPixelMultiMap` | AO/Rough/Metal 分离通道 | 需拆 RGB 通道 |
| `ksPerPixelMultiMap_damage` | 同上，忽略 damage | 降级 |
| `ksPerPixelReflection` | `+ reflection_probe` | 车漆 |
| `ksPerPixelAT` | StandardMaterial3D + alpha scissor | 透明 |
| `ksGrass` | **无对应** → 退化绿色贴图 + 风动画 | 已知损失 |
| `ksTree` | 退化 billboard | 已知损失 |
| `ksSkyBox` | 映射到 Godot Sky | 天空 |
| `ksWind` | 简化风场 | 部分支持 |
| 未知 / CSP 扩展 | `StandardMaterial3D` + **明确日志** | 不静默 |

**参数映射**：`diffuse` → albedo，`normal` → normal，`specular`/`detail` → roughness/metallic（按 shader 解释通道）。

## 12. 车辆资产加载

### 12.1 收集阶段

扫描 `<AC>/cars/<car>/`，按目录约定收集：

- 参数文件组（ini 集合）
- 主模型 kn5（可能是多个：body / cockpit / LOD）
- collider.kn5（碰撞体，若有）
- acd
- 皮肤列表（`skins/` 下各子目录）
- 音频（sfx/）
- 动画（animations/）
- UI（ui/ui_car.json、preview.png）

### 12.2 解析阶段

```
1. 读 ini 集合 → CarParams
   ├─ 标记来源：FromIni / FromAcd / Inferred
   └─ 缺失必填项 → 报错并列出
2. 读 acd → 补齐 + 交叉校验
3. 读主 kn5 → Kn5Scene（或命中缓存）
4. 读 collider.kn5（若有）→ 物理碰撞网格
   若无 → 用视觉网格简化生成凸包
5. 读皮肤 dds → 覆盖 albedo 槽位
6. 读 sfx → 音频事件表（见第 14 节）
7. 读 animations → 动画片段表（见第 15 节）
```

### 12.3 构造阶段

```
Kn5Scene.meshes → ArrayMesh（每个 mesh 一个 surface）
Kn5Scene.materials → StandardMaterial3D（按映射表）
Kn5Scene.nodes → Node3D 树（保留层级与命名）
识别特殊节点：
  - WHEEL_LF / RF / LR / RR（轮子挂点）
  - STEER（方向盘）
  - DRIVER（驾驶员挂点）
  - BRAKE_CALIPER / DISK
  - 灯光节点（刹车灯、转向灯）
  - 可动翼片（DRS）
CarParams → 物理核心 Vehicle 结构
```

### 12.4 运行时绑定

每渲染帧：

- 物理输出四轮位姿 → 写入对应 Node3D 的 transform
- 车身位姿 → VehicleRoot.transform
- 方向盘转角 → STEER 节点局部旋转
- 悬挂压缩 → 按悬挂节点动画或程序化位移
- 车轮旋转 → 按物理转速累加

**时间预算**（中等车模 ~50 万三角面）：

- 参数解析 < 10 ms
- kn5 解析 < 500 ms（命中缓存 < 50 ms）
- 纹理解码异步，不阻塞进入场景

## 13. 赛道资产加载

### 13.1 赛道特有内容

相比车辆，赛道多了：

- 路面材质与摩擦系数（`surfaces.ini`）
- 起跑线、pit 区、检查点、缓冲区
- AI 线（`fast_lane.ai` / `pit_lane.ai`）
- 相机（`camera.ini`）
- 边界（`borders.ini`）
- DRS / KERS 区（`drs_zones.ini`）
- 小地图（`map.png` + `map.ini`）
- 赛道特有配置（`track.ini`）

### 13.2 surfaces.ini 与摩擦

```ini
[SURFACE_0]
KEY = 1
FRICTION = 0.98
DAMPING = 0.0
SOUND = tarmac
WAV = <name>
FF_EFFECT = 1
$$

[SURFACE_1]
KEY = 2
FRICTION = 0.75
...
```

处理：

- kn5 材质的 `ksTrackSurface` shader 带 `surfaceKey` 参数
- 与 surfaces.ini 的 `KEY` 匹配，得到摩擦系数
- 物理层按当前轮胎所在面查询摩擦，影响 Fx/Fy 峰值
- 未匹配的 surface key → 用默认值 0.98 并记警告

### 13.3 物理碰撞网格

- 赛道 kn5 可能数百万面，**不能直接用渲染网格做碰撞**
- 策略：
  - 标注 `COLLISION` 或 `-col` 后缀的节点 → 专用碰撞网格
  - 无标注 → 按节点名启发式（road / curb / grass / wall）
  - 路面用 `ConcavePolygonShape3D`（trimesh）
  - 墙体用凸包分解（`ConvexPolygonShape3D` 数组），性能更好
- 碰撞网格与渲染网格分离，碰撞用低模

### 13.4 分块流式加载

赛道太大，全量加载会卡死：

```
1. 按 kn5 顶层节点分块（AC 赛道通常已按区域分节点）
2. 每块计算 AABB
3. 视锥 + 距离裁剪：可见块加载高精度，远处加载低 LOD
4. 背景线程流式加载/卸载
5. 碰撞网格优先加载（车辆需要立即有地面）
```

### 13.5 AI 线

`fast_lane.ai` 提供：

- 中心线点列（含宽度）
- 每条线的速度建议
- 切线方向

用途：

- 单机 AI 对手的路径
- 赛会系统的赛道进度计算（圈数、分段）
- 小地图车辆位置归一化
- 离线赛车的理想线参考

### 13.6 相机

`camera.ini` 定义赛道固定机位（重播、观察）：

```
[CAMERA_0]
NAME = Start
POS = x,y,z
POS_CAR = x,y,z
LOOK = x,y,z
LOOK_CAR = x,y,z
```

映射到 Godot `Camera3D` + 插值切换。

### 13.7 小地图

- `map.png` + `map.ini`（含边界框与旋转）
- 映射到 2D 纹理，玩家位置按 AI 线归一化坐标投影
- 若缺 map.ini，从 AI 线自动推算边界

## 14. 音频系统

### 14.1 现实约束

AC 音频用 **FMOD**，`.bank` 是 FMOD 专有格式。完整实现 FMOD 运行时不现实。

### 14.2 三阶段方案

**阶段 A（MVP）**：程序化合成

- 引擎声：基于转速的谐波合成 + 负载调制
- 轮胎声：基于滑移率/载荷的噪声调制
- 风噪：基于车速
- 碰撞：基于冲量的短噪声

参数来自 `car.ini` 的 `[AUDIO]` 段（若有）与经验默认值。

**阶段 B**：WAV 直读

- 若模组 `sfx/` 下提供 `.wav` 样本（部分模组有），直接解码播放
- 按 FMOD 事件名映射到播放逻辑（引擎层、排气层、超转、回火）

**阶段 C**：bank 解析（P2，可选）

- 解析 FMOD bank 格式，提取样本与事件结构
- 自行实现事件系统（参数化播放、多层混合、随机化）
- 不做 FMOD 完整 DSP，只做本游戏需要的部分

### 14.3 GUID 映射

`GUIDS.txt` 提供事件名 ↔ GUID：

```
{xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx} event:/cars/engine/xxx
```

解析后建立事件表，供代码按语义名触发。

### 14.4 优先级

音频不影响物理与公平性，**优先级低于物理与渲染**。阶段 A 足够支撑 MVP。

## 15. 动画系统

### 15.1 ksanim 解析

`.ksanim` 是二进制动画片段：

- 通道：位置 / 旋转 / 缩放
- 关键帧：时间、值、插值方式
- 绑定目标：kn5 节点名

### 15.2 animations 配置

`.animations` 是文本，定义动画状态机与触发条件：

```ini
[ANIMATION_0]
NAME = wheel_lf_rotate
FILENAME = wheel_spin.ksanim
NODE = WHEEL_LF
SPEED = 1.0
LOOP = 1
```

### 15.3 用途

| 动画 | 驱动源 |
|---|---|
| 方向盘旋转 | 物理转向角 |
| 车轮旋转 | 物理转速 |
| 悬挂压缩 | 悬挂行程 |
| 驾驶员手臂 | 转向角 + 挡位 |
| 雨刷 | 天气系统 |
| 可动翼片 | DRS 状态 |
| 散热片/百叶窗 | 水温 |

### 15.4 实现

- 解析 ksanim → 内部 `AnimationClip` 结构
- 运行时按驱动值采样（程序化驱动，不按时间播放）
- 方向盘/车轮/悬挂这类**程序化驱动**，不用 ksanim
- ksanim 主要用于驾驶员、雨刷、可动部件等装饰动画

## 16. AI 线与赛事数据

### 16.1 ai 格式解析

`.ai` 二进制：

- 头：线数、点数
- 每条线：点数组（位置、宽度、速度建议、类型标记）
- 多线：fast_lane / pit_lane / slow_lane（部分赛道）

### 16.2 用途

| 用途 | 说明 |
|---|---|
| 单机 AI | 路径跟随 + 速度规划 |
| 赛道进度 | 圈数判定、分段计时、 Sector |
| 小地图 | 坐标归一化 |
| 赛会 | 起跑线、pit 入口/出口判定 |
| 离线赛车的理想线 | 参考线绘制 |

### 16.3 赛道进度算法

```
1. 把 AI 线投影成 1D 参数 s ∈ [0, 1)
2. 每帧找车辆最近的 AI 线点 → 得到 s
3. s 从 0.9+ 跳到 0.0- → 完成一圈
4. s 回退超过阈值 → 判定逆向
5. Sector = s 的三等分
```

## 18. CSP 扩展兼容策略

CSP（Custom Shaders Patch）极大扩展了 AC，也是模组生态的重要部分。

### 18.1 分级支持

| 级别 | 内容 | 策略 |
|---|---|---|
| **L0 完全支持** | 物理扩展（extra grip、tyre model 覆盖） | 映射到本引擎对应参数 |
| **L1 部分支持** | 材质扩展（新 shader 特性） | 降级到最接近的内置材质 + 日志 |
| **L2 忽略** | 视觉特效（粒子、贴花、灯光扩展） | 跳过 + 日志 |
| **L3 拒绝** | 加密 kn5、自定义 Lua 脚本 | 明确报错，不加载 |

### 18.2 ext_config.ini

赛道/车辆的 CSP 配置，按节处理：

- `[LIGHTING]` → 光照覆盖（可部分支持）
- `[SHADER_REPLACEMENT_...]` → 材质替换（L1）
- `[TEXTURE_OVERRIDE_...]` → 纹理覆盖（可支持）
- `[SCRIPT_...]` → Lua 脚本（L3 拒绝）
- `[PARTICLES_...]` → 粒子（L2 忽略）

### 18.3 原则

**每一条未支持的 CSP 特性都必须在加载日志中列出**，含文件名与节名。玩家能查到"这台车的哪些特性没生效"。

## 19. 缓存策略（可删，非打包）

### 19.1 定位

**纯加速，可随时删，源文件变了自动失效**。不是资产，不参与分发。

### 19.2 实现

```
位置：<user_cache>/racing/
  ├── kn5/<hash>.bin         ← 序列化的 Kn5Scene
  ├── tex/<hash>.bin         ← 解码后的 RGBA8 + mipmap
  └── bank/<hash>.bin        ← 解码后的样本表

key = sha256(绝对规范化路径 + 文件大小 + mtime + 解析器版本)
失效 = key 不匹配 → 重新解析
```

### 19.3 规则

- 缓存只是解析结果的二进制快照
- 删掉缓存后功能完全正常，只是首次加载慢
- 缓存不替代源文件，不参与分发与传输
- **缓存版本号随解析器版本变化**，解析器改了自动全失效
- 不缓存到模组目录内（不污染用户资产）

**这不是"重新打包"**：没有产出任何用户可见的资产文件，没有格式转换，没有"转换步骤"。

## 20. 兼容性与错误处理

### 20.1 策略表

| 情况 | 策略 |
|---|---|
| 标准 AC 模组 | 完整支持 |
| CSP 扩展模组 | 部分支持，未支持特性降级 + 日志 |
| 加密 / 加壳 kn5 | 明确报错，提示不支持 |
| 缺参数模组 | 模板补全 + 标记 `Inferred` |
| 格式异常 | 报错并给出具体字段/偏移，不崩溃 |
| FMOD bank 缺失 | 降级到程序化音频 |
| AI 线缺失 | 禁用 AI 对手，玩家模式仍可玩 |
| map.png 缺失 | 从 AI 线自动生成小地图 |
| 纹理缺失 | 用棋盘格占位纹理 + 日志 |

### 20.2 错误报告

统一错误类型：

```rust
pub enum AssetError {
    Io { path: PathBuf, source: io::Error },
    Kn5Parse { path: PathBuf, offset: u64, detail: String },
    IniMissingSection { file: PathBuf, section: String },
    IniMissingKey { file: PathBuf, section: String, key: String },
    UnsupportedShader { material: String, shader: String },
    EncryptedKn5 { path: PathBuf },
    XmlMismatch { /* ... */ },
    // ...
}
```

**原则**：每个错误都能定位到**具体文件 + 具体位置 + 具体原因**，用户能据此修模组或报告作者。

### 20.3 加载报告

每次加载产出一份报告（JSON），含：

- 解析成功/失败的文件清单
- 所有 `Inferred` 字段及来源
- 所有未支持的 shader / CSP 特性
- 所有降级项

报告在 UI 可查看，也进遥测（服务端据此判断该模组是否适竞技）。

## 21. 事件采集（事实源）

从第一天就采集，服务端积分与评分都依赖它。

```rust
pub struct RaceEvent {
    pub t: f64,                    // 比赛时间
    pub seq: u64,                  // 单调递增序号
    pub kind: EventKind,
    pub actors: Vec<u32>,          // 涉及车辆
    pub data: EventData,
}

pub enum EventKind {
    RaceStart, RaceFinish,
    LapComplete { lap: u32, time: f64, sector_times: [f64; 3] },
    Overtake { from: u32, to: u32 },
    Contact { impulse: f32, point: [f32; 3] },
    OffTrack { duration: f64 },
    PitEntry, PitExit,
    Penalty { kind: PenaltyKind },
    Retirement { reason: RetirementReason },
}
```

要求：

- 事件由物理核心在权威状态下产生，不是渲染层猜测
- 事件流 append-only，带序号
- 每场输出：事件流 + 输入日志哈希 + 结果摘要 + manifest 哈希
- 直接对接 Server 项目的"结果包协议"

## 23. 物理验证阶梯

| 层级 | 方法 | 通过标准 | 何时做 |
|---|---|---|---|
| L1 | 单元测试 | 各力模型输出符合解析解 | 持续 |
| L2 | 稳态测试 | 定圆、定速转向、直线加速与理论一致 | 每模型完成后 |
| L3 | **AC 遥测对比** | 圈速误差 < 2%，峰值横向加速度 < 5% | **第一天就做** |
| L4 | 主观对比 | 与 AC 交替驾驶，手感一致 | 有可玩版本后 |
| L5 | 车手盲测 | 老玩家分辨不出 | 后期 |

**L3 是唯一严格验证**。具体做法：

1. 选官方车（参数完整）+ 官方赛道
2. AC 里用固定输入跑 3 圈，记录遥测
3. 本引擎用相同输入跑
4. 逐项对比，超标定位到具体模型

## 25. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| AC 参数缺失严重 | 物理不准 | 模板补全 + `Inferred` 标记 + 优先官方车 |
| kn5 格式变体多 | 部分模组加载失败 | 明确报错 + 不支持清单 + 社区反馈 |
| FMOD bank 逆向成本极高 | 音频缺失 | 三阶段方案，阶段 A 程序化合成够用 |
| CSP 特性无限扩展 | 永远追不上 | 分级支持 + 明确日志 + 社区贡献接口 |
| 赛道规模导致加载慢 | 体验差 | 分块流式 + 碰撞体简化 + 缓存 |
| 轮胎调参耗时 | 进度拖延 | 先官方车校准，模组车后置 |
| 物理与渲染耦合抖动 | 手感差 | 严格固定步长 + 插值，第一天就做对 |
| 零基础 Godot 踩坑 | 进度拖延 | 严格按第 22 节六阶段推进，不跳步 |
| 格式逆向踩坑 | 进度拖延 | 每格式配 golden test，真实模组样本库 |

## 26. 与 Server 项目的接口

唯一契约：**结果包**（见 Server 项目方案第 6 节）。

主项目负责产出：

```json
{
  "match_id": "...",
  "manifest_hash": "车池+赛道+物理版本哈希",
  "input_log_hash": "...",
  "replay_commitment": "...",
  "events": [...],
  "results": { "...": "..." }
}
```

交给 Server Core 签名上报。**主项目不计算积分**，积分由服务端算。

主项目同时负责：

- manifest 哈希计算（车池/赛道/物理版本/环境锁定）
- 输入日志的记录与哈希
- 事件流的产出
- 回放数据的本地留存（7 天，供抽检）
